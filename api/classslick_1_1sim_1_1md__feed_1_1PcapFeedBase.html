Detailed Description

A venue's market data replayed from captured multicast, behind a control channel.

The venue derives from this and supplies what is protocol: how a packet reaches its handler, and whether the handler has built the book. This class owns the rest:

LOADING open the capture files and read each line up to the window's begin SYNCING feed the handler at full speed until it reports the book built, which the snapshot capture does. No market data is published: the publisher's gate is closed. READY the book is held at that point. The capture is not read further. REPLAYING a client's START begins it: the gate opens, so the publisher sends every instrument from the held book on, and packets go to the handler paced by speed. A START that comes earlier is kept until READY. FINISHED the window is replayed out. (ERROR: a file or the sync failed.)

Every state change goes to the clients on the control channel, along with progress about once a second while the feed works.

Time: the sim runs on the wall clock. Pacing waits on it, and events are stamped with event_time_ns() - the wall time their capture time maps to - not the capture's own time. FeedStatusMessage::current_ns reports the capture time.

Threads: poll() and everything virtual run on the exchange thread, like every feed. The control channel and the capture reader have threads of their own.
