Detailed Description

Helpers for a venue whose one config entry describes several independent exchange instances, such as CME's market segments or ICE's silos.

What a venue's exchange instance (CME segment, ICE silo) does for a pcap feed, the same way for every venue.

Each instance becomes its own Exchange, on its own thread.

None of it needs libpcap: a config that names a pcap feed has to be understood, and refused, in every build.

Expands a venue's config entry into one config per instance listed under list_key.

Without list_key, the entry is the only instance. With it, each instance starts from the entry's other keys, which all instances share, merge-patched with the instance's own. RFC 7386 merges objects key by key and replaces anything else, arrays included. An instance with "enabled": false is skipped.

An instance without a name gets default_name(instance, index); the single entry without list_key gets venue.

◆ make_exchanges()

template<typename T , typename Base = Exchange>
std::vector< std::unique_ptr< Base > > slick::sim::exch::make_exchanges ( const nlohmann::json &  config)

The factory body SLICK_SIM_REGISTER_VENUE registers.

A template because only there does if constexpr discard the branch that does not apply - in the macro's plain function, a single-instance venue's missing create_instances would still fail to compile.

Base is always Exchange. It is a parameter only to make the vector's type dependent: unique_ptr's destructor is constexpr in C++23, and clang instantiates a constexpr destructor as soon as it sees a non-dependent use of it, so a plain vector<unique_ptr<Exchange>> local would need Exchange complete wherever this header is included. Dependent, it waits for instantiation, where T is complete.
