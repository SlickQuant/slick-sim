Detailed Description

Correlates an in-flight HTTP request with its execution report.

A handler records what it is waiting for and returns. The gateway's drain completes the response when a report arrives; the request timer completes it on timeout. Polling with a 100us sleep would block the gateway's only event loop for the full timeout, once per entry for a batch request.

Predicates support the handlers' different correlation keys: client_order_id for creates and request timestamps for cancels. The list is bounded by the requests in flight, so scanning costs less than maintaining several indexes.

All methods run on the gateway's loop thread.
