Detailed Description

The channel between a pcap replay and its clients, apart from the market data (multicast) and the orders (the TCP order gateway), neither of which can say that the book is still loading or ask for the replay to begin.

A small TCP server. A client connects, is told the current FeedStatusMessage, and is sent every later one; it sends START when it is ready for the market data. Framing is ControlHeader (common/control_messages.hpp). A client that sends anything else is disconnected.

Threads: the server thread owns the sockets and parses what arrives; the exchange thread calls publish_status() and take_start(). Status goes through a lock-free slick::queue, which overwrites the oldest entry if the server thread falls QUEUE_SLOTS behind; START is an atomic flag.

stop() must run before destruction, as with TcpOrderGateway; the destructor does it.
