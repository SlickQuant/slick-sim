Detailed Description

Replays several captured multicast groups as one packet stream in capture-time order.

A reader thread decodes the capture files, merges the lines by timestamp, and hands batches to the exchange thread through a bounded lock-free ring (slick::spsc_queue). The reader waits when the ring is full, so a consumer that stops draining (a replay waiting for its client to start it) holds the capture where it is and loses nothing, unlike the lossy live-feed queue.

The consumer looks at the next packet with peek() before taking it with pop(), so a pacer can hold a packet back until its time. Both are for one thread, and the rest of the interface may be called from any thread.

Only packets with begin_ns <= timestamp <= end_ns are replayed. Files of consecutive days overlap, so a line's next file skips everything up to the time its previous file reached, and nothing repeats.
