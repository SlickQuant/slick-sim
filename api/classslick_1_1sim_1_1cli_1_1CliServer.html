Detailed Description

The simulator's command port: a small TCP server on its own thread that takes CliRequestMessages (common/control_messages.hpp) and hands each one, through a lock-free CliEndpoint, to the thread that owns what it changes.

sim is the main thread; a venue's commands go to its order gateways' threads, which keep the state they change, so the matching loop never sees a command.

A target names a set of endpoints: a venue's config key (cme) is all of its endpoints, and every /-prefix of an endpoint's name addresses those under it (ice/<silo> is every BGW of that silo). A command goes to each endpoint of its target and is answered once all of them have, or after reply_timeout, with one line per endpoint.

A client has one request answered at a time, so its replies come in order; the rest wait in the server. A client that sends anything malformed is disconnected.

Like every slick-socket server it listens on all interfaces, with no authentication.

stop() must run before the endpoints go; the destructor does it.
