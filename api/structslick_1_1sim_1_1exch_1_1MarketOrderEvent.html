Detailed Description

One of the venue's own orders entering, changing or leaving the book, from an order-by-order feed, in the simulator's units.

Applied with Exchange::applyMarketOrder, which rests it as a phantom order beside the clients'.

◆ book_priority

uint64_t slick::sim::exch::MarketOrderEvent::book_priority = 0

The order's place in its level's queue: drawn from OrderBook::nextOrderPriority() when it joined, and kept until it requeues.

An order a client took entirely rests again under it, back where it was. Never 0: OrderBookL3 reads a priority of 0 as "use the timestamp" and would sort the order against the clients' sequence-numbered priorities.

◆ qty

qty_t slick::sim::exch::MarketOrderEvent::qty = 0

Remaining visible quantity, 0 on DELETE.

A CHANGE carries the venue's quantity, and applying it always restores the book to it. It can equal what the venue reported before while the book holds less, because a client order took some.
