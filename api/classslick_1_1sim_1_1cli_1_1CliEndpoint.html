Detailed Description

Where the CLI server's commands reach a thread that owns some state (the main thread, or a venue's order gateway), and where that thread's answers come back.

Two lock-free slick::queues, one each way. The CLI server thread is the only one that posts and takes replies, the owner thread the only one that serves. post() refuses while MAX_IN_FLIGHT commands are unanswered, so neither ring, lossy when lapped, is lapped.

The owner calls serve() from its loop. With nothing waiting it is one acquire load.
