Detailed Description

The transport half of a live multicast feed: one receiver thread that polls every joined group ("line"), handing the packets to the exchange thread through one lock-free queue.

Nothing here takes a lock. Only the exchange thread touches the book, as it drains the queue into the venue's protocol handler.

A line is a small integer below MAX_LINES that the venue chooses (its enum). The venue can leave a line's group while it has no use for it, such as a snapshot loop while the book is live, and rejoin it on a gap (set_joined).

Header-only, so the md_feed target stays free of slick-socket: a venue that includes this links slick::socket itself.

Config keys, read from the feed's config entry: queue_size (bytes, default 16 MiB), max_packets_per_poll (256), interface and receive_buffer_size for every receiver. Each line's group is { "address", "port" } under its key.

receive_buffer_size (bytes, default 64 MiB) is each socket's SO_RCVBUF: what the kernel holds while the receiver thread is descheduled. The kernel drops a burst beyond it, so size it for the stall, not for one packet. The read buffer is separate and fixed (MAX_DATAGRAM). The kernel caps it at net.core.rmem_max (Linux), so raise that too. receiver_cpu (default -1) pins the receiver thread to that core. It busy-polls its sockets, so a pinned thread keeps the core at 100%; an unpinned one sleeps RECEIVER_IDLE_SLEEP between empty sweeps instead. A pin that cannot be made (no such core, outside the process's cpuset, an unsupported platform) is logged and leaves the thread unpinned, so it sleeps too rather than spin on a core it does not own. A receiver_cpu that is not a number throws from the constructor, like queue_size.

The queue is fixed and lossy, like every slick::queue: should the exchange thread fall far enough behind, a receiver overwrites packets nobody has drained, and loss_count() counts their bytes. The venue's own sequence numbers are what turn that into a gap it can recover from. A packet is also held back from the queue until the receiver that reserved its slot has copied it in, so one stalled copy delays the packets behind it - never reorders them.

◆ change_membership()

virtual int slick::sim::md_feed::MulticastPacketFeed::change_membership ( uint8_t line,
bool join )
inlineprotectedvirtual

Joins or leaves line's group.

Returns 0 once the socket is as asked, an error, or MEMBERSHIP_PENDING: the change is under way and the same call is to be made again. Virtual so a test can make it fail; only called when the membership has to change, or a change handed to the receiver thread is still in flight.

A socket is only ever touched by the receiver thread, so the change is handed to it, and each call looks for its answer without waiting, so the exchange thread cannot be held up by a receiver that is descheduled. A change that was handed over and is no longer wanted is withdrawn if the thread has not taken it yet, so it is never made behind the caller's back; one the thread has begun is waited out across calls, then followed by the one now wanted. EIO is a join the thread could not make; slick-socket logs the socket error behind it.

◆ set_joined()

void slick::sim::md_feed::MulticastPacketFeed::set_joined ( uint8_t line,
bool joined,
uint64_t now_ns )
inline

Exchange thread, from poll().

Leaves or rejoins line's group, so the network stops sending what nobody reads. A line not wanted is muted at once, which also drops what is already in the socket buffer. The membership counts as changed only once the socket call succeeds: a failed one is logged once and tried again every MEMBERSHIP_RETRY_NS until it does, so recovery never waits on a group that was not rejoined. The receiver thread makes the change itself, as its sockets are its own: this hands it over and returns, then finds the answer on a later call (see change_membership), so the exchange thread never waits for it. Two compares when nothing is pending, so it is cheap to call every poll. Before start(), or for a line with no group, only the mute changes.
